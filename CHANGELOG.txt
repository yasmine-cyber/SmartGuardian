SmartGuardian - Résumé des changements
======================================

AUTH & INSCRIPTION
-----------------
- Signup et login connectés à Supabase (public.utilisateurs, auth.users)
- Rôles : Patient et Aidant (proche) s'inscrivent ; Admin et Médecin sont provisionnés
- Trigger handle_new_user crée automatiquement la ligne dans utilisateurs
- Confirmation email activée : lien envoyé avant première connexion
- Message dédié si "email non confirmé" ou "rate limit" (trop de tentatives)

BASE DE DONNÉES
---------------
- Schéma aligné : utilisateurs, patients, medecins, proche_patient
- patients.maladies (array) : choix des maladies au signup (patient uniquement)
- patients.date_naissance, utilisateurs.telephone stockés
- Option "Autre" pour maladie : champ texte pour préciser

VALIDATION DES CHAMPS
--------------------
- Nom complet : minimum 2 parties (Prénom Nom)
- Email : format valide (ex. nom@domaine.com)
- Mot de passe : minimum 6 caractères
- Téléphone : exactement 8 chiffres
- Date de naissance : pas de date future, max 120 ans
- Calendrier : dates après aujourd'hui désactivées
- Maladies (patient) : au moins une sélectionnée ; si "Autre", texte requis

INTERFACE
---------
- Nom d'utilisateur dynamique : Bonjour {nom} depuis la base (sidebar + PatientDashboard)
- Titre app : SmartGuardian 
- Port dev : 5173

NOUVELLES FONCTIONNALITÉS (pull récent)
---------------------------------------
- Routes protégées avec `ProtectedRoute` et page `Unauthorized` pour gérer l'accès selon le rôle.
- Pages mot de passe oublié et réinitialisation : `ForgotPassword` et `ResetPassword` intégrées au flux Supabase.
- Page `PatientProfile` : consultation des informations saisies à l'inscription (profil patient) depuis `/patient/profile`.



UPDATE 
---------------------------------------
Un admin peut créer un compte médecin depuis le panneau d'administration.
Supabase envoie automatiquement un email d'invitation au médecin, qui clique sur le lien pour définir son mot de passe et accéder à son espace.

Fichiers touchés

1. supabase/functions/create-medecin/index.ts ← NOUVEAU
Edge Function Deno déployée sur Supabase.
Ce qu'elle fait :

Vérifie que l'appelant est authentifié et a le rôle admin
Appelle inviteUserByEmail avec les données du médecin
Redirige vers http://localhost:5173/set-password (à changer en prod)

Points importants :

Doit être déployée avec --no-verify-jwt ou JWT désactivé dans le Dashboard
Utilise SUPABASE_SERVICE_ROLE_KEY pour les appels admin
Le trigger handle_new_user en base crée automatiquement les entrées utilisateurs et medecins


2. src/pages/AdminDashboard.tsx ← MODIFIÉ
Formulaire de création médecin ajouté dans l'onglet "Utilisateurs".
Champs du formulaire :

Nom complet (obligatoire)
E-mail (obligatoire)
Téléphone (optionnel)
Spécialité (obligatoire)
Numéro de licence (obligatoire)

3. src/pages/SetPassword.tsx ← NOUVEAU
Page où le médecin définit son mot de passe après avoir cliqué le lien d'invitation.
Ce qu'elle fait :

Écoute l'événement SIGNED_IN déclenché par le token d'invitation
Affiche un formulaire de création de mot de passe avec indicateur de force
Redirige vers /doctor après succès
Redirige vers /login si aucun token valide après 5 secondes


4. src/App.tsx ← MODIFIÉ
Route ajoutée dans <Routes> (route publique, non protégée par ProtectedRoute).
tsximport SetPassword from "@/pages/SetPassword";

// Dans <Routes> :
<Route path="/set-password" element={<SetPassword />} />
Pourquoi non protégée ? Le médecin n'a pas encore de session quand il arrive sur cette page — ProtectedRoute le redirigerait vers /login avant que Supabase traite le token.
